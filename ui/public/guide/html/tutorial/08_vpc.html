VPC

VPC는 내부의 서브넷을 생성해 ACL로 접속을 제한할 수 있는 가상 네트워크 그룹이다. VPC를 통해 Virtual Router를 공유하는 Isolated Network를 생성할 수 있으며, 이 Isolated Network들이 VPC에서 설정한 ACL에 따라 접근을 허용하거나 거부당한다. 아래 VPC 예시와 같이 서로 다른 VPC간의 서브넷들은 서로 격리된 상태이다.

[그림 1] VPC 예시


VPC간의 서브넷들끼리 통신하기 위해서는 VPC Gateway에 Public IP를 할당해서 외부 접속을 허용하거나 사이트 간 사설네트워크(VPN)을 통해 연결시켜야 한다. 아래의 그림은 Public IP를 할당해서 외부 접속을 허용하는 모습이다.

[그림 2] 사이트 간 사설 네트워크(VPN)


지금까지 예시로 나온 VPC-A, VPC-B와 같은 VPC를 만들기 위해 다음과 같은 과정을 거치게 된다.

아래 VPC 생성 화면을 통해 VPC를 추가한다.

입력해야하는 데이터는

  • 이름

  • Zone

  • 도메인

  • 계정

  • CIDR

VPC 예시에 해당하는 CIDR을 입력해보자. VPC-A의 경우, 입력 값은 10.1.0.0/16 이고 VPC-B의 경우, 입력 값은 10.2.0.0/16이다.

[그림 3] VPC 생성 화면


VPC를 생성했다면 서브넷을 생성한다.

[그림 4] 서브넷 생성 화면 에서 다음 정보들을 입력해서 생성한다.

  • 이름

  • 게이트웨이

    • CIDR을 입력한다.

  • 넷마스크

  • ACL

각 VPC 별로 서브넷을 2개씩 생성하는 것이 목표다.

서브넷은 VPC의 CIDR 안에 포함되는 CIDR을 가진다. 또한 ACL을 등록해서 해당 서브넷에 대해 세밀한 접근 제어가 가능하다. 이번에는 VPC-A-WEB과 VPC-A-APP, VPC-B-WEB을 다음과 같이 만든다.

  • VPC-A-WEB: 10.1.1.0/24

  • VPC-A-APP: 10.1.2.0/24

  • VPC-A-APP: 10.2.1.0/24

ACL을 입력할 때는 VPC-A-WEB과 VPC-A-APP, VPC-B-WEB의 경우에는 default_allow를 사용해서 모든 접속을 허용하게 만든다.

[그림 4] 서브넷 생성 화면


생성된 서브넷을 가상 네트워크 페이지에서 확인하면 아래 Isolated로 인식되는 서브넷에서 보이듯 Isolated Network로 인식되는 것을 알 수 있다.

[그림 5] Isolated로 인식되는 서브넷


이후 VPC-A-WEB과 VPC-A-APP, VPC-B-WEB에 각각 VM을 하나씩 생성한다. 아래 VPC-A-WEB에서 VPC-A-APP과 VPC-B-WEB으로 ping 결과에서 알 수 있듯, VPC-A-WEB과 VPC-A-APP은 같은 VPC에 있어서 ping으로 통신할 수 있다. 그러나 VPC-B-WEB과는 VPC가 달라 ping이 loss 된다.

[그림 6] VPC-A-WEB에서 VPC-A-APP과 VPC-B-WEB으로 ping 결과


이번에는 같은 VPC라고 해도 ACL에 의해서 접근이 제어되도록 작업해보자. 서브넷에 ACL 목록을 지정하면 해당 목록의 규칙에 의해서 접근이 제어된다. VPC-B ACL 예시에서 VM-B-APP의 경우, vpc-b-deny라는 ACL이 적용 되어있다. 이 ACL은 다른 접속은 허용하지만 22번 포트는 deny하는 상태다.

[그림 7] VPC-B ACL 예시


ACL은 default로 default_allow와 default_deny가 존재한다. 예시로 보여준 vpc-b-deny는 사용자가 직접 만들어서 적용한 것이다. 아래 ACL 목록 생성 화면과 같이 운영자가 ACL을 추가로 생성할 수 있다.

[그림 8] ACL 목록 생성 화면


생성된 ACL 목록에 규칙을 추가해야 한다. ACL 규칙 생성 화면에서 아래 정보를 입력한다.

  • #규칙: 자동으로 지정(규칙번호는 오름차순으로 적용)

  • 전송원 CIDR: 해당 ACL의 영향을 받을 상대방을 지정하는 CIDR

  • 동작: Allow/Deny

  • 프로토콜

  • 시작 포트

  • 종료 포트

  • 트래픽 유형

[그림 9] ACL 규칙 생성 화면


port 22번 금지 규칙 생성

  • #규칙: 자동으로 입력

  • 전송원 CIDR: 0.0.0.0/0

  • 동작: 거절

  • 프로토콜: tcp

  • 시작 포트: 22

  • 종료 포트: 22

  • 트래픽 유형: Ingeress

모든 통신 허용 규칙 생성

  • #규칙: 자동으로 입력

  • 전송원 CIDR: 0.0.0.0/0

  • 동작: 허용

  • 프로토콜: tcp

  • 시작 포트: 0

  • 종료 포트: 0

  • 트래픽 유형: Ingeress

위의 정보로 생성 요청하면 ACL 목록 규칙 생성 결과와 같이 등록된다.
